# AED Accessibility in Castilla y Leon

Urban network science project for measuring access to automated external
defibrillators (AED/DESA) across Castilla y Leon.

The first baseline combines:

1. JCyL DESA locations, geocoded with the official CartoCiudad service.
2. JCyL municipality points and population.
3. A complete Castilla y Leon OpenStreetMap extract from Geofabrik.

The project uses DuckDB as the local analytical store. Raw downloads are
immutable and are not committed to Git.

## Setup

Requirements: Python 3.11+, `uv`, and `just`.

```bash
just install
just init-db
```

Place the downloaded JCyL files at the paths in `config/sources.yaml`:

- `data/raw/aed.csv`
- `data/raw/municipalities.csv`
- `data/raw/castilla-y-leon-latest.osm.pbf`

The JCyL files may use Spanish column names and either CSV or JSON format.
The normalizer accepts common aliases, but the source headers should be
checked before running the full pipeline.

Run the current tabular ingestion and geocoding pipeline with:

```bash
just run
```

Create the static AED map after geocoding:

```bash
just map
```

This writes `reports/aed_map.png` with the official IGN Mapa Base WMS
basemap. The map contains only AED records with valid CartoCiudad coordinates.
The pipeline also writes `reports/aed_geocode_audit.csv` with the selected
provider, precision, status, coordinates, and matched address for every AED.

## Hospital accessibility map

The second-stage analysis estimates normal driving time from each accepted AED
location to the nearest emergency-capable hospital. It uses the dated
Geofabrik OSM extract, Pyrosm to build a directed road graph, and Pandana to
calculate network travel times. It is a modeled road-time estimate, not an
ambulance response-time observation: it does not include dispatch, loading,
traffic, or emergency-vehicle priority.

The downloaded official sources are `data/raw/hospitals.csv` (general
catalogue) and `data/raw/hospital_emergency.csv` (the 14 hospitals with
hospital emergency services). The general catalogue has addresses but no
coordinates, so `data/interim/hospitals_geocoded.csv` is generated by matching
the 14 emergency hospitals to representative facility points in the dated OSM
extract. The original portal downloads remain immutable.

Run the stages in this order:

```bash
just hospitals
just network
just accessibility
just isochrone
```

The final figure is written to
`reports/figures/aed_hospital_isochrone.png`. It shows a continuous gradient
for the nearest reachable hospital, hospital markers, and accepted AEDs
 colored by their routed time. The color scale spans the valid values in each
 run and has no fixed upper cap. The accessibility stage uses a 360-minute
 search bound only to control computation; exact reachable values below that
 bound are retained in `node_hospital_access` and `aed_hospital_access`.

The regional isochrone masks all cells outside the Castilla y León
administrative boundary stored at
`data/interim/castilla_y_leon_boundary.gpkg`.

The accessibility stage reads the current accepted rows from `aed_geocodes`
when it runs. It does not modify geocoding code or cache rows, so the
geolocation agent can replace those points before rerunning `just
accessibility`.

## Population access from cadastral buildings

The building workflow allocates each municipality's official population to
residential Cadastre INSPIRE building footprints with Tobler area-weighted
interpolation. It then snaps building centroids to a bidirectional OSM walking
network at 4.8 km/h and assigns each building to its nearest AED. The output
reports population within 5, 10, and 15 walking minutes. Routing searches up
to 360 minutes so that long-distance times are retained; the reporting bands
remain 5, 10, and 15 minutes.

Before walking access is calculated, the network is labeled by weakly
connected component. Components with fewer than 10 nodes are excluded, and
AED/building snaps are limited to 500 metres from a substantial component.
This prevents isolated OSM fragments from producing false long routes while
preserving small rural settlement networks.

Run it with:

```bash
just catastro-buildings-repair
just building-population
just walking-network
just population-access
```

The map is written to `reports/figures/population_aed_access.png` and the
building-level and municipality-level results are stored in DuckDB. The
population audit is written to `reports/building_population_audit.csv`.
Building footprints from the Cadastre WFS can be rejected for large extents;
the repair command tiles those requests and records any remaining failures in
`data/raw/catastro_buildings/manifest.csv`. Missing municipalities are filled
from OSM where possible and from local Nominatim population points where OSM
has no building features. The source used for every estimate is stored in
`building_population.building_source`.

To plot municipality-level population coverage as three lines, run:

```bash
just municipality-plot
```

The x-axis ranks municipalities from largest to smallest interpolated
population, avoiding an unreadable axis with thousands of municipality names.
The underlying percentages are exported to
`reports/municipality_population_access.csv`.

For the population-weighted distribution of resident walking time to the
nearest AED, run:

```bash
just population-distribution
```

This writes `reports/figures/population_aed_proximity_distribution.png` and
`reports/population_aed_proximity_distribution.csv`. The median is weighted by
estimated residents rather than by building count. Residents not reached by
the 360-minute query are shown separately and are not treated as having a
360-minute travel time.

For a municipality dot plot of 5-, 10-, and 15-minute population coverage with
unweighted and population-weighted medians, run `just municipality-dotplot`.

For a detailed blueprint-scale example, run:

```bash
just leon-map
```

This writes `reports/figures/leon_building_aed_access.png` and exports the
joined León building layer to `data/processed/leon_building_aed_access.gpkg`.
León uses cadastral code `24900` but INE municipality code `24089`; the
population crosswalk therefore uses the cadastral manifest municipality name
and province rather than assuming that the numeric codes are identical.

The ten largest municipalities can be rendered with:

```bash
just major-city-maps
```

Maps are written under `reports/figures/cities/` and joined building layers
under `data/processed/city_buildings/`. Municipalities whose cadastral source
is unavailable can be processed with the generalized OSM fallback.

Zamora can still be rendered with its explicit OSM fallback using
`just zamora-osm-buildings`, `just population-access`, and `just zamora-map`.
For all missing municipalities, use `just osm-fill-missing` before
`just population-access`. OSM and Nominatim-derived records are labeled and
must not be interpreted as cadastral building observations.

Geocoding runs in batches of 250 addresses with a progress bar and resumes
from the DuckDB cache if interrupted. Override the batch size when needed:

```bash
just run -- --geocode-batch-size 100
```

Use `just test` and `just lint` before submitting changes.

## LLM-assisted review

The optional GEPETO workflow reviews only unresolved addresses. Put the
authenticated values in the ignored `.env` file:

```text
GEPETO_API_KEY=...
GEPETO_BASE_URL=https://gepeto.bsc.es/api
GEPETO_MODEL=...
MAPBOX_ACCESS_TOKEN=...
```

List available GEPETO models, then select one in `.env`:

```bash
just gepeto-models
just llm-geocode
just map
```

GEPETO produces search hypotheses and chooses among real Mapbox candidates;
it is never allowed to generate coordinates. Accepted results are stored with
the model, prompt version, input hash, candidate data, decision, and rationale
in `llm_geocode_reviews`.

## Cadastral building footprints

The optional building layer uses the official Spanish Directorate General for
Cadastre INSPIRE Buildings (BU) municipality downloads. The configured nine
Castilla y Leon provincial feeds are downloaded as immutable ZIP archives, and
only files ending in `.building.gml` are extracted. Building-part and other
construction files are excluded.

Run the complete download and footprint extraction with:

```bash
just catastro-buildings
```

This writes the raw archives and feed snapshots below
`data/raw/catastro_buildings/`, a SHA-256 manifest at
`data/raw/catastro_buildings/manifest.csv`, and extracted footprint GML files
below `data/raw/catastro_buildings/footprints/`.

If a municipality ZIP endpoint is temporarily unavailable, use
`just catastro-buildings-wfs`. This uses the official BU WFS with each
municipality bounding box and filters returned features by cadastral municipality
code. The manifest records whether each archive came from the ZIP or WFS route.

The source feed was updated in February 2026 during this run. The source
requires attribution to the Dirección General del Catastro; the project keeps
the feed URLs, update timestamps, and checksums in the local manifest.

## Data acquisition

The exact JCyL download URLs and SHA-256 checksums are recorded in
`config/sources.yaml`. The OSM baseline is the dated Geofabrik extract at:

`https://download.geofabrik.de/europe/spain/castilla-y-leon-260906.osm.pbf`

For reproducibility, prefer a dated Geofabrik file rather than `latest` for a
published run, and record its download date and checksum.

## Data model

- `municipalities`: municipality identifiers, population, and source points.
- `aed_locations`: normalized DESA records and their source addresses.
- `aed_geocodes`: permanent CartoCiudad response cache keyed by normalized
  address. Failed or ambiguous matches remain available for review.
- `hospitals`: configured emergency-hospital destinations and provenance.
- `road_nodes` and `road_edges`: converted directed OSM driving graph.
- `node_hospital_access` and `aed_hospital_access`: Pandana travel-time results.
- `pipeline_runs`: source and execution provenance.

PBF conversion is a separate network-ingestion stage. Pyrosm preserves OSM
one-way semantics and the project persists explicit directed edges with
travel-time weights calculated from `maxspeed`. Missing speed tags use
documented highway-class defaults in `desfibrilator.network`.

Geocoding uses CartoCiudad first, selecting candidates that match the source
municipality and province. Unresolved records can be sent once to bounded
Nominatim with a one-request-per-second delay; both providers and all raw
responses are recorded in `aed_geocode_attempts`. Exact-address and
street-level matches are shown with different symbols in the PNG map.
Nominatim-derived points carry OpenStreetMap contributor attribution and ODbL
licensing information in the map output.

Mapbox is an optional final fallback. Enable permanent storage in the Mapbox
account, rotate the token, export the replacement as `MAPBOX_ACCESS_TOKEN`,
and run `just run --use-mapbox --skip-cartociudad --skip-fallback`. Only
unresolved keys without a previous Mapbox attempt are sent in batches of 100.
Use `--retry-mapbox-rejected` only after changing Mapbox matching logic; it
makes one finite retry pass over previously rejected keys.

To refresh the existing CartoCiudad cache after a candidate-selection change,
run `just run --refresh-cartociudad --skip-fallback`. The fallback can then
be run independently with `just run --skip-cartociudad`.
Use `--retry-nominatim-rejected` only after changing the fallback matching
logic; ordinary runs do not repeat rejected public-service requests.

## Why not Overture first?

Overture can be a useful comparison source, but Geofabrik OSM is the better
baseline here because it is a regional extract, has established routing
tooling and licensing documentation, and can be updated independently of the
municipality identifiers. Use Overture later to assess coverage and attribute
differences, not to replace JCyL or IGN/IDECyL authoritative boundaries.

Municipality polygons should come from IGN/CNIG or IDECyL because they carry
official Spanish identifiers. Overture is not the preferred source for those
boundaries.

Pandana is distributed under AGPL-3.0-or-later and Pyrosm under MIT. Check
the resulting licensing obligations before redistributing an installed
analysis environment or derivative software.
